# 时间线约束的叙事记忆智能体

## 一句话概念

在长篇创作过程中，系统后台自动把已经完成的文本转化为一个按故事内时间线组织的叙事记忆系统，并基于角色视角生成受限记忆的 agent。某个情节点上的角色 agent 只能访问它在故事当时应该知道的信息，不能访问未来剧情，从而帮助作者做创意推演、角色行为模拟和前后矛盾检查。

## 核心直觉

普通写作助手通常是把全文当成上下文，然后以作者的全知视角回答问题。这个想法的关键差异是：memory 不按作者写作顺序组织，而是按故事世界内部的时间线和角色可见性组织。

也就是说，系统不是简单地问“全文里有什么”，而是问：

| 问题 | 含义 |
| --- | --- |
| 这个情节点之前发生了什么？ | 只允许访问故事时间上的过去 |
| 这个角色亲历、听说、推断了什么？ | 只允许访问角色视角内的信息 |
| 哪些信息是秘密、误解或未来才揭露的？ | 防止 agent 使用不该知道的事实 |
| 如果从这个角色当时的记忆出发，它会怎么行动？ | 用受限记忆做剧情推演 |

因此，memory 的时间可见性本身就是叙事逻辑的一部分。

## 概念描述

我设想的是一个嵌入写作流程的叙事智能体系统。作者在创作长篇故事时，后台会持续解析已经完成的文本，抽取事件、角色状态、人物关系、世界规则、伏笔、秘密和因果链，并构建一个以“故事内时间线”为索引的 memory 模块。

基于这个 memory，系统可以生成不同角色或叙事视角下的 agent。每个 agent 的记忆都受到时间和视角约束：它只能看到在当前情节点之前发生、且按设定它有理由知道的信息，而不能访问未来章节或其他角色隐藏的信息。

当作者后续遇到创意瓶颈、想测试人物行为是否合理，或者想检查后文是否与前文冲突时，就可以让这些 agent 在受限记忆下进行推演、补全、质询或一致性审查。

## 系统模块

| 模块 | 作用 |
| --- | --- |
| 故事解析器 | 从正文中抽取事件、角色、地点、物品、承诺、秘密、伏笔和冲突 |
| 叙事时间线 | 把事件按故事内时间排序，而不是按作者写作顺序排序 |
| 角色记忆 | 为每个角色维护其知道的事实、经历、误解、目标和情绪状态 |
| 可见性控制 | 限制 agent 在某个时间点只能访问过去信息和其视角内信息 |
| 推演引擎 | 让角色 agent 根据当前记忆继续行动、对话或判断局势 |
| 一致性审计 | 用全局视角检查前后矛盾、伏笔未回收、角色动机断裂和未来信息泄露 |

## 两个核心使用场景

### 1. 创意推演

作者写到某个章节卡住时，可以选择一个情节点和一个角色，让系统从该角色当时的受限记忆出发进行推演。

示例问题：

- “从角色 A 在第 12 章结尾的认知状态出发，他下一步最可能做什么？”
- “如果角色 B 仍然不知道真相，她会如何解释刚刚发生的事件？”
- “在不揭露第 18 章秘密的前提下，第 10 章还能怎样推进冲突？”

这类推演不同于普通续写。它不是泛泛生成剧情，而是在角色已有记忆、目标、误解和情绪状态的约束下模拟下一步。

### 2. 叙事审计

作者写完后文后，可以让系统回头检查故事是否自洽。

示例问题：

- “第 5 章的角色是否不合理地知道了第 9 章才揭露的信息？”
- “这个伏笔在后文有没有被兑现？”
- “某个角色的态度变化有没有足够的中间事件支撑？”
- “是否存在时间线矛盾、因果断裂或动机跳变？”

这相当于一个带时间隔离机制的 plot-hole detector。

## 和 Agent Memory 综述的关系

这个想法可以用 `Forms - Functions - Dynamics` 框架拆解。

| 维度 | 对应到这个想法 |
| --- | --- |
| Forms | 叙事记忆主要是 token-level structured memory，包括时间线、角色图、事件图、秘密和伏笔索引 |
| Functions | factual memory 维护剧情事实，experiential memory 支持角色行为模式，working memory 支持当前情节点推演 |
| Dynamics | formation 从正文抽取记忆，evolution 处理冲突、更新和伏笔状态，retrieval 按时间和角色视角受限检索 |

其中最有研究价值的部分是 retrieval 和 visibility control。系统检索时不能简单取 top-k 相关内容，而要先判断：

1. 这个内容在故事内时间上是否已经发生；
2. 当前角色是否有理由知道；
3. 这个信息是否属于秘密、误解、传闻或未来揭示；
4. 当前任务需要的是角色主观视角还是作者全局审计视角。

## 可以强调的创新点

| 创新点 | 说明 |
| --- | --- |
| 故事内时间线索引 | memory 按 diegetic timeline 组织，而不是按写作顺序或文本顺序组织 |
| 角色视角可见性 | 不同角色拥有不同已知事实、误解、秘密和目标 |
| 未来信息隔离 | 某个情节点的 agent 不能访问未来剧情，避免全知视角污染推演 |
| 推演与审计双模式 | 既能帮助生成后续剧情，也能检查已有文本是否自洽 |
| 叙事 memory governance | 对秘密、伏笔、承诺、世界规则和角色状态做版本化管理 |

## 命名候选

- Timeline-Constrained Narrative Agents
- Chronology-Aware Story Agent
- Diegetic Memory Agents
- Narrative Memory Sandbox
- Temporally Grounded Narrative Agents

目前最贴切的名字是 **Diegetic Memory Agents**。它强调 agent 的记忆不是作者全知视角，而是嵌在故事世界内部的。

## 想要做成什么

这个想法最终想做的不是一个普通续写工具，而是一个面向长篇创作的 **narrative memory sandbox**。

它应该允许作者在任意情节点上打开一个受限视角：

- 选择某个故事时间点；
- 选择某个角色或叙事视角；
- 系统只加载这个时间点以前、且该角色应该知道的信息；
- 让角色 agent 基于自己的记忆、目标、误解和动机进行推演；
- 同时允许作者用全局视角检查剧情中是否存在矛盾、泄密、伏笔断裂或动机跳变。

比较理想的形态是：作者仍然掌握创作主导权，系统不替作者决定剧情，而是提供“受限视角下的可能性”和“全局视角下的风险提示”。

## 后续可以继续展开的问题

| 问题 | 可能方向 |
| --- | --- |
| 如何从自由文本稳定抽取事件时间线？ | event extraction、temporal ordering、chapter-level incremental parsing |
| 如何判断角色是否知道某个事实？ | viewpoint modeling、information propagation、dialogue evidence tracking |
| 如何表示秘密和误解？ | private memory、false belief state、confidence and provenance |
| 如何检测未来信息泄露？ | temporal access audit、character knowledge consistency check |
| 如何评价推演质量？ | human author preference、plot consistency、character motivation consistency |
| 如何避免系统替作者做过度决定？ | 提供多分支推演和审计理由，而不是单一路线续写 |
